    42→### API Routes (all return JSON, all under /api)
    43→- GET `/api/dashboard` → { stats, projects, charts, notifications, lowStockMaterials }
    44→- GET `/api/projects` (optional ?status=, ?managerId=) → { projects[] } (each project includes stages[], manager, overallProgress, plannedProgress, installationPct, _count)
    45→- POST `/api/projects` (body: {name, location, client, totalPanels, capacity, status, startDate, endDate, budget, managerId, description}) → { project }
    46→- GET `/api/projects/[id]` → { project } (includes stages, dailyProgress, tasks, expenses, documents, sCurve)
    47→- PUT `/api/projects/[id]` → { project }
    48→- DELETE `/api/projects/[id]` (admin only)
    49→- GET/PUT `/api/projects/[id]/stages` → { stages[] }; PUT body: { stages: [{id, name, plannedPct, actualPct, weight, status, startDate, endDate}] }
    50→- GET `/api/progress` (optional ?projectId=, ?from=, ?to=, ?limit=) → { entries[] }
    51→- POST `/api/progress` (body: {projectId, date, installedPanels, totalInstalled, manHours, workers, materialsUsed, equipmentUsed, workCompleted, workPending, siteStatus, remarks, photoUrls, gpsLocation}) → { entry }
    52→- DELETE `/api/progress/[id]`
    53→- GET `/api/tasks` (optional ?projectId=, ?status=, ?assignedToId=) → { tasks[] } (includes project, assignedTo, isOverdue)
    54→- POST `/api/tasks` (body: {title, description, projectId, assignedToId, assignedToName, team, priority, status, progress, startDate, dueDate, remarks}) → { task }
    55→- PUT `/api/tasks/[id]` → { task }
    56→- DELETE `/api/tasks/[id]`
    57→- GET `/api/workers` (optional ?projectId=, ?team=, ?status=) → { workers[] } (includes project, attendance[last 7])
    58→- POST `/api/workers` (body: {name, employeeId, role, team, projectId, phone, skillLevel, status}) → { worker }
    59→- PUT `/api/workers/[id]` → { worker }; POST `/api/workers/[id]` (body: {action: 'checkin'|'checkout'}) → { attendance }
    60→- DELETE `/api/workers/[id]`
    61→- GET `/api/attendance` (optional ?from=, ?to=, ?workerId=) → { records[] }
    62→- GET `/api/materials` (optional ?category=, ?lowStock=) → { materials[] } (includes transactions[last 5])
    63→- POST `/api/materials` (body: {name, category, unit, stockQty, minStockLevel, unitPrice, supplier}) → { material }
    64→- PUT/DELETE `/api/materials/[id]`
    65→- GET `/api/transactions` (optional ?materialId=, ?projectId=, ?type=) → { transactions[] }
    66→- POST `/api/transactions` (body: {materialId, projectId, type: 'Add'|'Issue'|'Return', qty, remarks, date}) → { transaction, newStock } (auto-updates stock)
    67→- GET `/api/expenses` (optional ?projectId=, ?category=, ?approvalStatus=) → { expenses[] }
    68→- POST `/api/expenses` (body: {date, projectId, category, description, amount, paidBy, approvalStatus, receiptUrl}) → { expense }
    69→- PUT/DELETE `/api/expenses/[id]`
    70→- GET `/api/safety/checklists` (optional ?projectId=, ?checklistType=) → { checklists[] }
    71→- POST `/api/safety/checklists` (body: {date, projectId, checklistType, helmet, safetyShoes, gloves, harness, workAreaClean, equipmentCondition, electricalSafety, location, remarks}) → { checklist } (auto-calculates compliancePct)
    72→- GET `/api/safety/incidents` (optional ?projectId=, ?type=, ?status=) → { incidents[] }
    73→- POST `/api/safety/incidents` (body: {date, projectId, type, severity, description, location, status, actionTaken}) → { incident }
    74→- PUT `/api/safety/incidents/[id]`
    75→- GET `/api/documents` (optional ?projectId=, ?category=) → { documents[] }
    76→- POST `/api/documents` (body: {name, category, projectId, fileUrl, fileType, fileSize, description}) → { document }
    77→- DELETE `/api/documents/[id]`
    78→- GET `/api/notifications` → { notifications[] }
    79→- PUT `/api/notifications/[id]` (body: {isRead}) → { notification }
    80→- GET `/api/users` → { users[] }; POST `/api/users` (body: {email, name, password, role, phone})
    81→- PUT/DELETE `/api/users/[id]`
    82→- GET `/api/reports/[type]` → { type, title, html, data } where type is one of: daily, weekly, monthly, manpower, material, expense, safety, project-summary, planned-vs-actual

   104→### Established Design Pattern (FOLLOW THIS)
